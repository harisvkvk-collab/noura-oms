# Noura OMS — Handoff Brief for Claude Code

## What this is
A custom Order Management System for an abaya business (in-store + online:
Instagram, WhatsApp, Facebook, TikTok — Shopify later). Retail only for now;
wholesale/export deferred to a future phase.

## What's already built (backend foundation — done, tested, working)
- **schema.sql** — full Postgres schema: customers, products/inventory,
  orders, order items/photos/notes, fulfillment timeline, payments, COD
  receivables, multi-leg shipments, couriers, purchases/suppliers,
  multi-currency, country-specific payment methods. Already run
  successfully in a live Supabase project.
- **policies.sql** — Row Level Security: authenticated staff get full
  access to business tables; courier_api_credentials is locked to
  backend-only (service_role) access. Already run and verified.
- **auth_setup.sql** — links staff_users to Supabase Auth via a trigger
  that auto-creates a staff profile on invite. Already run; one working
  admin account exists (Haris, role=admin), confirmed in the database.
- **adapters/types.ts** + **adapters/nextdrop.ts** — a courier adapter
  interface plus a working NextDrop implementation (createShipment,
  generatePostageLabel, webhook payload parsing). NextDrop API key has
  been generated by the client and needs to be set as a Supabase secret
  (NEXTDROP_API_KEY) — not yet deployed.
- **functions/nextdrop-webhook/index.ts** — Supabase Edge Function to
  receive NextDrop's webhook and update shipment_legs. Written, not yet
  deployed.
- **frontend/Login.tsx, supabaseClient.ts, App.tsx** — basic invite-only
  login flow scaffolded, not yet built out into a real app shell.

## What's next (this is the actual work)
1. Scaffold a real React (Vite) frontend project, wire in the existing
   Login.tsx / supabaseClient.ts / App.tsx as a starting point.
2. Build the screens already designed and approved by the client
   (described below) against live Supabase data.
3. Write the order-creation logic: generate order number, decrement stock
   via inventory_ledger, create payment or COD receivable record, create
   shipment (or skip shipment entirely for in-store orders), log to
   order_timeline.
4. Deploy the NextDrop webhook function and wire the real API key in as a
   Supabase secret (never hardcoded).
5. Aramex and Delhivery couriers exist in the DB as 'manual' status —
   their adapters aren't built yet (no API keys/docs finalized for
   Aramex; Delhivery needs a BD relationship with them first). Manual
   entry works for all couriers right now regardless.

## Screens already designed (build these, matching this behavior exactly)
- **Dashboard**: Overview tab (stat cards, Pending Actions grouped by
  Sales/Purchases/Inventory, Recent Orders list) + New Order tab.
- **New Order form**: customer search/add, order source (Instagram/
  WhatsApp/Facebook/TikTok/In-store), currency picker, line items table,
  reference photo upload (single "Add photo" button → native picker),
  notes textarea, payment method (incl. COD with per-courier default
  delivery fee, editable), courier picker. **In-store orders skip
  shipping/COD entirely and complete immediately via "Complete sale"** —
  no packing/postage/dispatch steps for those.
- **Order fulfillment timeline** (online orders only): Created → Confirm
  order (WhatsApp send is an optional checkbox, unchecked doesn't block
  progression) → Packed → Postage printed → Dispatched, each step
  timestamped with staff name.
- **Inventory**: category tabs (All/Abaya/Mukhawar/Accessory), stock
  status badges (in stock/low stock/out of stock).
- **Customers**: list + tabbed detail/add form (Details/Address incl.
  zip code/Notes), WhatsApp + call buttons next to phone number
  (wa.me link + tel: link — call button only meaningful on mobile).
- **Purchases**: PO list + creation form mirroring the Sales Order
  layout (supplier instead of customer, cost instead of price).
- **Courier COD receivables**: per-courier table (collected, fees
  deducted, net due), settlement tracking — stays manually entered,
  no courier currently exposes a settlement API.
- **Multi-leg shipment tracking**: for international orders, shows
  UAE outbound leg + destination-country local leg separately, each
  with its own courier/tracking/status.

## Key constraints to preserve
- Client is not a developer — keep explanations in plain language, avoid
  assuming technical background.
- No accounting software / general ledger — payment tracking only.
- Multi-currency: rate locked at order time (orders.exchange_rate_snapshot).
- COD is not offered in India — country_payment_methods table governs
  which payment methods show per delivery country (India: UPI/card only).
- Wholesale/export deferred — don't add wholesale pricing, credit terms,
  or export customs complexity unless explicitly asked.
